# Мои дела — ежедневник (PWA)

Календарь дел на месяц: задачи с временем, комментарии, переносы между днями,
статистика за неделю, пуш-уведомления, оффлайн-режим. Работает без сервера —
чистый HTML/CSS/JS, данные хранятся в браузере (localStorage).

## Что в папке

| Файл | Назначение |
|---|---|
| `index.html` | страница приложения |
| `app.js` | вся логика (календарь, дела, уведомления, бэкап) |
| `style.css` | оформление (светлая/тёмная/авто темы) |
| `sw.js` | service worker: оффлайн-кэш + будильники + показ пушей |
| `manifest.webmanifest` | манифест PWA (установка на телефон) |
| `icon.svg`, `icons/` | иконки (SVG, PNG 192/512, apple-touch 180) |
| `test_push_crypto.mjs` | независимая проверка криптографии Web Push (node) |
| `test_e2e_push.mjs` | сквозной тест пушей в headless Chrome (CDP) |

## Локальный запуск

```bash
cd DailyTasks
python -m http.server 8731
# открыть http://127.0.0.1:8731
```

Или любой статический сервер (`npx serve .` и т.п.).

## Публикация на GitHub Pages

1. Создай репозиторий на GitHub (например, `dailytasks`). Имя репозитория
   станет частью адреса: `https://<твой-логин>.github.io/dailytasks/`.
2. Загрузи в репозиторий **все файлы из этой папки** (кроме, по желанию,
   тест-скриптов `test_*.mjs` — они не нужны сайту). Пути в приложении
   относительные, поэтому оно работает и в подпапке, и в корне.
3. В репозитории: **Settings → Pages → Build and deployment → Source:
   Deploy from a branch → ветка main → папка / (root) → Save**.
4. Через 1–2 минуты приложение будет на `https://<твой-логин>.github.io/dailytasks/`.

Никакой сборки нет: что загрузил — то и работает. После обновления файлов
просто закоммить изменения (кэш обновится сам — версия кэша прописана в sw.js).

## Установка на телефон

- **Android (Chrome):** открой адрес приложения → меню ⋮ → «Добавить на главный
  экран» → «Установить». Появится иконка, приложение откроется без адресной строки.
- **iPhone (Safari):** открой адрес → кнопка «Поделиться» → «На экран домой».
  Пуш-уведомления на iPhone работают только после такой установки.

## Уведомления и напоминания — как это работает

Напоминание на время дела срабатывает, **пока приложение открыто** (вкладка или
установленное PWA в фоне/недавних). Это ограничение любого статического сайта
без сервера: код, который отправляет уведомление, должен в этот момент
выполняться. Если вкладка закрыта полностью — напоминание не отправится.

Каналы доставки (Настройки → Уведомления):

1. **Pushover** (по умолчанию, работает везде). Уведомление приходит в
   приложение Pushover **на телефоне**, даже когда приложение открыто на
   компьютере. Настройка:
   - на pushover.net создай аккаунт (User Key — на главной странице);
   - там же «Create an Application/Token» — получишь App Token;
   - вставь оба ключа в настройки приложения и нажми «Проверить уведомление».
2. **Web Push** — только в **Firefox**. В Chrome этот канал не работает: сервис
   push-уведомлений Google (FCM) не отдаёт CORS-заголовки, браузер блокирует
   отправку. Firefox (Mozilla autopush) CORS разрешает — там канал рабочий.

Кнопка «Проверить уведомление» честно показывает результат: при успехе —
«Тест отправлен», при ошибке — её текст в строке статуса.

## Данные

Хранятся в localStorage **на каждом устройстве отдельно**. Перенос между
устройствами — через бэкап: Настройки → «Экспорт (бэкап)» → файл .json →
на другом устройстве Настройки → «Импорт».

## Тесты

```bash
node test_push_crypto.mjs        # криптография Web Push (RFC 8291/8188, JWT ES256)
node test_e2e_push.mjs           # сквозной тест в headless Chrome
```

Для e2e-теста нужен запущенный Chrome с remote-debugging-port 9223 и
локальный сервер на 8731 (см. скрипт). E2e проверяет: подписку FCM,
доставку по каналу Pushover (iframe-POST), аккуратный отказ CORS у Web Push
в Chrome и срабатывание будильника внутри service worker.

## Известные ограничения

- Напоминания — только при открытом приложении (см. выше).
- Синхронизация между устройствами — только через бэкап-файл.
- Web Push в Chrome/iOS не работает (CORS у FCM/APNs) — используй Pushover.
